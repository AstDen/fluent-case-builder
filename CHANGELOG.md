# CHANGELOG

Все заметные изменения плагина. Формат — [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/),
версии — [semver](https://semver.org/lang/ru/).

## [0.3.0] — 2026-11-11

### Изменено
- Из публичного репозитория удалён проектный профиль с приватными данными: он остаётся локально и
  подключается через `config.profileDirs`.
- Добавлен синтетический профиль-пример `example-channel` (сетка → ламинарный решатель →
  инициализация → критерии → сохранение) — для обучения формату и проверки установки.
- Документация и данные очищены от упоминаний приватного проекта; кейс-специфичные позиционные
  строки в рецептах помечены `unverified` и не входят в публичный пакет.

## [0.2.1] — 2026-11-11

### Исправлено / уточнено
- Документация установки: установка/обновление из git требует перезапуска DSH; описаны признак
  `failed to import: Cannot find package '@deepseek-ai/dsh-tools'` и обходной путь (локальный клон).
- Профиль-пример `example-channel`: заметка о статусе движка (unzip-flat и optional-ассеты реализованы).
- Синхронизирован контракт отчёта с реализацией: коды находок — из `data/rules/diagnostics.json`,
  `case.mode: existing`, `environment.fluent.source: path`, лицензия только в `environment.license`.

## [0.2.0] — 2026-11-11

### Добавлено
- `fluent_task_report` — самодостаточный отчёт о задаче (JSON + Markdown) для мейнтейнера:
  окружение и версия Fluent, постановка, ответы интервью, кейс/спека, проверка журнала,
  лог запуска, автоматический анализ ошибок и список пробелов (`docs/REPORT_FORMAT.md`).
- `fluent_task_log` — журнал заметок исполнителя (`task-notes.jsonl`), автоматически попадает в отчёт.
- Диагностика ошибок по логу: `data/rules/diagnostics.json` (12 кодов: лицензия, UDF, зоны, Scheme,
  batch-подтверждение, crash, OOM и др.), анализ стадий выполнения и покрытия журнала рецептами.
- Петля обучения: `scripts/ingest-report.mjs` агрегирует присланные отчёты в
  `learning/aggregate.json` + `learning/backlog.md` (`docs/MAINTAINING.md`).
- Переносимая конфигурация: внешний `~/.config/fluent-case-builder/config.json` (env `FLUENT_CONFIG`),
  переменные окружения, автоопределение Fluent; KB стала необязательной.
- `profileDirs` — дополнительные каталоги профилей кейсов.
- Публичная документация: `README.md`, `docs/INSTALL.md`, `examples/`, MIT-лицензия.

### Изменено
- `fluent_case_generate` теперь материализует и универсальный spec: `setup_case.jou` из проверенных
  рецептов + `case.json` (нужен `outputDir`); профильный путь сохранён.
- Машинно-специфичные пути убраны из упаковочного `cordis.patch.yml` (публикуемый пакет переносим);
  источники в данных переведены на относительные (`KB/…`, `<projects>/…`).
- `caseRoots` по умолчанию — `~/fluent-cases`; `allowRun` по умолчанию `false`.
- Импорт заметок из `task-notes.jsonl` в отчёт; отчёт по умолчанию пишется в `<caseDir>/analysis`.

### Исправлено
- Валидатор журнала: порядок точных совпадений, пробельная форма команд, меню-контейнеры,
  категории `hidden-known` / `journal-2025`; без настроенного индекса — `verdict: skipped`.
- Статус запуска: успешная настройка с хвостовой ошибкой batch-подтверждения больше не «failed».
- Профиль с `outputRoot` без `profileRoots` теперь даёт понятную ошибку с подсказкой вместо пути вне `caseRoots`.
- Отчёт: версия Fluent определяется по полному логу (не по усечённому хвосту), покрытие журнала
  считается и для готового кейса, заметки подхватываются из `task-notes.jsonl`.

## [0.1.0] — 2026-11-11

### Добавлено
- Первая версия: 10 инструментов (`fluent_case_*`, `fluent_kb_*`), пример профиля `example-channel`,

- Универсальная спецификация кейса (`docs/CASE_SPEC.md`) и компилятор журнала из рецептов.
- Проверено: рендер профиля байт-в-байт с эталоном; живой прогон Fluent 2026 R1 → `.cas.h5/.dat.h5`.
